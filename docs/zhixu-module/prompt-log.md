## 条目 2

- **使用工具**:ZCode(GLM 模型);Node `--check`;本地静态服务器;ZCode 内置浏览器自动化(Playwright)。
- **我的 Prompt**:"继续"(共两次,分别发生在阶段1确认后与浏览器测试过程中;含义:按已确认的阶段计划继续执行阶段2–5)。
- **AI 返回结果**:连续完成阶段2–5 的编码与测试——
  - 阶段2(v0.1):任务增删改查 + localStorage 持久化 + 表单校验 + 确认弹窗 + 空状态 + toast;
  - 阶段3(v0.3):导航与三视图、仪表盘统计条、筛选工具栏、状态徽章、`js/planner.js` 计划算法;

  - 全部版本归档到 `docs/versions/`。
- **过程中的重要往返**:①浏览器冒烟时发现旧缓存干扰(页面混合加载新旧脚本),AI 改用带 no-store 头的本地服务器解决;②初版计划算法存在"逾期任务挤占今天容量"的调度缺陷,在测试中发现并重写为按可行性窗口末端排序的 EDF;③GUI 视觉检查发现 `[hidden]` 被 `.btn` 的 display 覆盖、筛选下拉框宽度异常,均修复;④自动化会话原生键鼠输入中途失效,改用 DOM 事件派发继续测试并在 tests.md 如实记录。
