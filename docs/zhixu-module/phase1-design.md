- 版本:v0.1-design(2026-10-25)

- 技术栈:HTML + CSS + 原生 JavaScript,无后端、无构建、无外部依赖,双击 `index.html` 即可运行(file:// 协议兼容)

## 1. 需求拆解

### 1.1 产品定位

面向大学生的学习任务规划网页:记录作业/考试/项目任务 → 管理截止日期 → 生成**可解释**的学习计划 → 跟踪完成情况。核心卖点(创意性维度):计划不是黑盒,"每条安排都讲得出理由";所有数据真实本地存储,不造假数据。

### 1.2 功能需求(FR)

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1 | 任务管理 | 新增/编辑/删除/标记完成;字段:标题(必填)、分类(必填)、截止日期(必填)、优先级(必填,默认"中")、预计耗时(必填,默认 1h,步进 0.5h)、备注(选填);必填校验 + 行内错误提示;删除需二次确认 |
| FR-2 | 分类与筛选 | 固定四类:课程/作业/考试/项目;按状态(全部/待办/已完成/已逾期/今日截止/即将截止)、分类、关键词(标题+备注,不区分大小写)组合筛选,条件为 AND;显示结果计数,可一键清除 |
| FR-3 | 截止提醒 | 基于真实系统日期计算剩余天数;四态:已逾期/今日截止/即将截止(≤3天)/普通;**状态 = 文字标签 + 图标 + 颜色三重编码**,不单靠颜色;已完成任务不再显示逾期 |
| FR-4 | 学习计划 | 设置计划周期(天数,默认 7)与每日可用时间(小时,默认 3);算法依据截止日期(升序)→ 优先级 → 预计耗时生成按日安排,每条附中文理由;时间不足时**显著警告并列出受影响任务与缺口**,绝不静默丢弃或谎称全部安排完 |
| FR-5 | 仪表盘 | 总数/已完成/待办/逾期/完成率五项统计,全部实时来自真实数据;总数为 0 时完成率显示"—"(不做除零) |
| FR-6 | 持久化 | localStorage 存储;启动探测存储可用性,不可用时降级内存模式并显著提示;读取时结构校验,损坏数据给出恢复提示,不白屏 |
| FR-7 | 数据备份 | 导出 JSON(含 meta 与 tasks,Blob + a[download],文件名带时间戳);导入前校验(app 标识/数组/逐条字段),不合法整体拒绝或逐条跳过并报告;导入提供"合并"(按 id,冲突取 updatedAt 较新)与"覆盖"(二次确认)两种模式,导入后报告结果 |
| FR-8 | 体验与可访问性 | 空状态引导;toast 操作反馈;键盘可达(Tab/Enter/Esc,弹窗焦点管理);所有表单控件有显式 label;aria-live 播报结果;响应式(≥960 桌面 / 600–960 平板 / <600 手机),触控目标 ≥44px |

## 2. 用户使用流程

**首次使用**:打开页面 → 空状态引导"添加第一个任务" → 填表(标题/分类/截止/优先级/耗时/备注)→ 校验通过保存 → 列表出现任务并显示剩余天数 → 继续添加 → 切到"学习计划"页 → 设周期与每日时间 → 生成 → 查看按日安排与理由;有"时间不足"警告则调整参数重新生成 → 回任务页勾选完成,完成率上升。

**日常使用**:打开 → 看仪表盘与逾期/今日截止徽章 → 筛"今日截止"逐项完成 → 搜索/筛选定位任务 → 编辑或删除。

**备份/恢复**:数据页导出 JSON 存档;换设备或清缓存后导入,选合并或覆盖。

## 4. 数据结构

### 4.1 localStorage

| 键 | 内容 |
|---|---|
| `zhixu.tasks.v1` | Task 数组的 JSON |
| `zhixu.settings.v1` | `{ "planDays": 7, "dailyHours": 3 }`(计划偏好记忆,可恢复默认) |

### 4.2 Task 对象

```json
{
  "id": "t_1730000000000_ab12",
  "title": "数据结构第3章习题",
  "category": "homework",
  "dueDate": "2026-10-30",
  "priority": "high",
  "estimateHours": 2.5,
  "note": "习题3.1-3.6,交到学习通",
  "done": false,
  "createdAt": "2026-10-25T09:00:00.000Z",
  "updatedAt": "2026-10-25T09:00:00.000Z"
}
```

字段规范:

| 字段 | 类型 | 校验规则 |
|---|---|---|
| id | string | `t_<时间戳>_<4位随机>`,导入时若重复按合并规则处理 |
| title | string | trim 后 1–100 字符,**必填** |
| category | enum | `course` / `homework` / `exam` / `project`,**必填** |
| dueDate | string | `YYYY-MM-DD`(本地日期字符串),**必填**,合法日历日期 |
| priority | enum | `high` / `medium` / `low`,**必填**,默认 `medium` |
| estimateHours | number | 0.5–99,0.5 的整数倍,**必填**,默认 1 |
| note | string | ≤500 字符,选填,默认 "" |
| done | boolean | 默认 false |
| createdAt / updatedAt | string | ISO 8601 |

### 4.3 导出文件格式

```json
{
  "meta": { "app": "zhixu", "version": 1, "exportedAt": "2026-10-25T…Z", "count": 12 },
  "tasks": [ …Task ]
}
```

### 4.4 日期策略(关键决策)

内部**只使用 `YYYY-MM-DD` 本地日期字符串**;"今天"取 `new Date()` 的本地年月日;天数差用 `new Date(y, m-1, d)` 构造后计算并四舍五入(规避时区与夏令时偏移);**绝不用** `new Date("YYYY-MM-DD")`(会被解析为 UTC)或 UTC 毫秒差比较跨日。所有展示/判断随真实系统时间变化,无硬编码演示日期。

## 5. 核心函数设计

文件结构(普通 script,按序加载,保证 file:// 可用):

```
zhixu/
├── index.html      结构 + 三视图 + 弹窗模板
├── style.css       全部样式(含响应式)
├── js/
│   ├── storage.js  持久化 + 备份导入导出校验
│   ├── domain.js   任务领域纯函数(状态/筛选/统计)
│   ├── planner.js  学习计划算法(纯函数)
│   ├── ui.js       DOM 渲染与交互
│   └── app.js      入口:初始化 + 事件绑定
├── README.md / tests.md
└── docs/           设计文档、prompt-log、dev-log、demo-script、版本归档
```

### 5.1 storage.js

| 函数 | 签名 | 职责 |
|---|---|---|
| isStorageAvailable | `() => boolean` | 探测 localStorage(try/catch 读写探针) |
| validateTask | `(raw: any) => Task \| null` | 单条字段级校验与规范化;加载与导入共用 |
| loadTasks | `() => { tasks: Task[], mode: "storage"\|"memory", warning?: string }` | 读取 + 解析 + 逐条校验;损坏条目剔除并计数;整体损坏时带 warning 由 UI 提示恢复 |
| saveTasks | `(tasks: Task[]) => boolean` | 序列化写入;失败返回 false,UI 弹"数据可能未被保存" |
| exportBackup | `(tasks: Task[]) => void` | 组装 meta + tasks,Blob + a[download] 下载 |
| parseImport | `(text: string) => { ok: boolean, error?: string, tasks?: Task[], skipped: number }` | 导入校验:JSON 可解析、meta.app==="zhixu"、tasks 为数组、逐条 validateTask(不合法跳过并计数) |
| mergeImport | `(current: Task[], incoming: Task[]) => { added, replaced }` | 合并:id 冲突取 updatedAt 新者 |
| todayStr | `() => "YYYY-MM-DD"` | 本地今天(全项目唯一取"今天"入口) |

### 5.2 domain.js(纯函数,不碰 DOM/localStorage,便于测试)

| 函数 | 签名 | 职责 |
|---|---|---|
| daysUntil | `(dueDate: string, today: string) => number` | 自然日差,逾期为负 |
| getDueStatus | `(task: Task, today: string) => "overdue" \| "today" \| "soon" \| "normal" \| "done"` | done 优先返回;soon = 1–3 天 |
| filterTasks | `(tasks, {status, category, keyword}) => Task[]` | 三条件 AND 组合 |
| computeStats | `(tasks) => { total, done, todo, overdue, rate: number \| null }` | overdue 仅计未完成;total=0 时 rate=null(UI 显示"—") |
| sortTasks | `(tasks) => Task[]` | 未完成在前 → dueDate 升序 → 优先级 → createdAt |
| createTask / updateTask | 输入 → Task | 生成 id 与时间戳;update 刷新 updatedAt |

### 5.3 planner.js(纯函数)

```
generatePlan(tasks, { startDate, days, dailyHours })
  → {
      days:      [{ date, capacity, blocks: [{ taskId, hours }], remaining }],
      scheduled: [{ taskId, startDay, endDay, hoursPerDay, reason }],   // reason 为中文解释
      warnings:  [{ taskId, type: "infeasible" | "overdue", need, got, message }],
      summary:   { totalNeed, totalCapacity, feasible }
    }
```

算法(EDF 贪心,单人学习场景下可证明最优的可抢占策略):

1. **候选**:未完成,且(已逾期 或 截止日 ≤ 周期最后一天)。
2. **排序**:dueDate 升序(逾期最先)→ 优先级权重(high 3 / medium 2 / low 1)降序 → 预计耗时降序(大任务先启动,避免末期塞不下)。
3. **装填**:从周期第一天起,每天容量 dailyHours;按排序逐任务、按 0.5h 粒度装填,任务可跨日拆分;只能装入"不晚于该任务截止日"的日期。
4. **不可行判定**:任务在截止日当天结束仍未装满所需小时 → 记入 warnings(含"还缺 X 小时"),并在结果顶部显著警示;绝不静默丢弃。
5. **理由生成**:模板化中文句子,例:"截止最近(10-27)且优先级高 → 安排在前 2 天,每天 2h";"已逾期 2 天,建议最先补上"。
6. **边界**:days ≥ 1、0.5 ≤ dailyHours ≤ 16,非法输入直接拒绝并提示。

### 5.4 ui.js / app.js

- `renderAll()` / `renderStats()` / `renderTaskList()`(DocumentFragment + 事件委托)
- `openTaskModal(mode, task?)` / `closeTaskModal()`:焦点陷阱、Esc 关闭、关闭后归还焦点
- `handleTaskSubmit`:校验 → 行内错误(`aria-invalid` + `aria-describedby`)→ 成功 toast
- `handleToggleDone(id)`、`handleDelete(id)`(确认框)、`handleEdit(id)`
- `handleGeneratePlan()`:调 generatePlan,渲染按日分组 + 理由 + 警告区
- `handleImportFile(file)`:FileReader → parseImport → 选择合并/覆盖 → 执行 → 结果报告 toast
- `toast(msg, type)`:统一反馈,aria-live 区域播报

## 6. 技术风险与对策

| # | 风险 | 对策 |
|---|---|---|
| 1 | file:// 下 ES modules 被 CORS 拦截,双击打不开 | 全部普通 `<script>`,不用 import/export |
| 2 | 时区/DST 导致"今日/逾期"误判 | 统一本地 YYYY-MM-DD;daysUntil 用本地 Date 构造 + round;单点 todayStr() |
| 3 | localStorage 被禁(隐私模式)/ 写满 | 启动探测 → 内存模式 + 常驻提示;保存失败 toast,不静默 |
| 4 | 存储数据被手改/损坏 → 白屏 | try/catch + 逐条校验;损坏提示"清空重开 / 导出原始内容留证" |
| 5 | 计划算法边界(0 天周期、超大耗时)死循环/NaN | 入参强校验;循环上界 = 任务数 × 天数 |
| 6 | 单文件过大难维护 | 按 storage/domain/planner/ui/app 五文件拆分,职责单一 |
| 7 | 焦点/键盘管理遗漏,可访问性不达标 | 弹窗焦点陷阱 + Esc + 归还焦点,列入阶段5测试清单 |
| 8 | `<input type="date">` 各浏览器样式不一 | 统一 read 值为 YYYY-MM-DD;样式适度重置;不依赖其内部 UI 细节 |

## 9. 待确认决策点(见对话中的提问)

1. 计划中单个任务超过单日剩余时间:**跨日拆分**(推荐)还是整块顺延?
2. 分类体系:**固定四类**(推荐,范围可控)还是允许自定义分类?
3. 阶段1设计整体是否通过,进入阶段2?
